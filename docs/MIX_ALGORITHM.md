# ASIC Mix Control — алгоритм расчёта микса

## 1. Область расчёта

Расчёт выполняется:

- только после сканирования;
- только для одного выбранного ЦОДа;
- отдельно для каждой модели платы `boardModel`;
- только по онлайн ASIC с `1/3` или `2/3` рабочих плат.

ASIC `0/3` и `3/3` в расчёт не попадают.

## 2. Роли

### Реципиент

ASIC, которому не хватает рабочих плат до полного состояния `3/3`.

- `2/3` требует 1 плату;
- `1/3` требует 2 платы.

### Донор

ASIC, который полностью разбирается и отдаёт все свои рабочие платы.

- `2/3` отдаёт 2 платы;
- `1/3` отдаёт 1 плату;
- после операции состояние донора — `0/3`.

## 3. Приоритет

Реципиенты сортируются по потребности:

1. `2/3` — требуют одну плату;
2. `1/3` — требуют две платы.

Это позволяет сначала закрыть максимальное количество устройств одной платой.

## 4. Подбор доноров

Для выбранного количества реципиентов сервер считает суммарную потребность:

```text
needed = Σ (3 - workingBoards)
```

Из оставшихся кандидатов подбирается набор доноров, рабочие платы которого равны `needed`.

Излишек не допускается: каждый выбранный донор полностью разбирается и все его рабочие платы должны быть распределены. Если точного баланса нет, такой вариант микса не предлагается.

## 5. Практические примеры

### Пример A: один донор `1/3`, три реципиента `2/3`

```text
Донор: 1 рабочая плата
Каждый реципиент: требуется 1 плата
```

Результат:

```text
1 донор → 1 реципиент
2 реципиента остаются неиспользованными
```

Донор становится `0/3`, выбранный реципиент — `3/3`.

### Пример B: один донор `2/3`, два реципиента `2/3`

```text
Донор: 2 рабочие платы
Каждый реципиент: требуется 1 плата
```

Результат:

```text
1 донор → 2 реципиента
```

Донор становится `0/3`, оба реципиента — `3/3`.

### Пример B2: один донор `2/3`, один реципиент `2/3`

```text
Донор отдаёт 2 платы, реципиенту нужна 1 плата.
```

Точный баланс невозможен: одна плата останется нераспределённой, поэтому микс не предлагается. Донор должен полностью перейти в `0/3`.

### Пример C: один донор `1/3`, один реципиент `1/3`

```text
Донор: 1 плата
Реципиент: требуется 2 платы
```

Полный микс невозможен. Оба устройства остаются неиспользованными.

### Пример D: два донора `1/3`, один реципиент `1/3`

```text
Доноры: 1 + 1 = 2 платы
Реципиент: требуется 2 платы
```

Результат:

```text
2 донора → 1 реципиент
```

Оба донора становятся `0/3`, реципиент — `3/3`.

### Пример E: донор `2/3`, реципиент `1/3`

```text
Донор: 2 платы
Реципиент: требуется 2 платы
```

Результат:

```text
1 донор → 1 реципиент
```

## 6. Неиспользуемые устройства

Устройства, которые не вошли в выбранный баланс, попадают в `unused`.

Интерфейс показывает их в отдельном визуальном блоке:

```text
Не используются в текущем миксе
```

Они не попадают в кнопку печати результата группы.

## 7. Печать

Кнопка печати группы формирует этикетки только из:

- `usedRecipients`;
- `usedDonors`.

Для каждой этикетки печатаются:

- последние две части IP;
- роль;
- уникальные модели плат;
- список нерабочих плат.

Индивидуальная кнопка рядом с устройством печатает только выбранный ASIC, включая устройство из блока неиспользуемых.
