# ASIC Mix Control — модель данных

## 1. ЦОД

```json
{
  "id": "uuid",
  "name": "ЦОД · зал A",
  "start": "10.1.38.1",
  "end": "10.1.38.254",
  "cidr": "",
  "createdAt": "2026-10-04T00:00:00.000Z"
}
```

Поля:

- `id` — UUID, создаётся сервером;
- `name` — 2–80 символов;
- `start` — начальный IPv4;
- `end` — конечный IPv4;
- `cidr` — альтернативная запись диапазона;
- `createdAt` — ISO timestamp.

Используется либо `start/end`, либо `cidr`. При сохранении CIDR поля `start` и `end` могут быть пустыми.

## 2. Устройство ASIC

Обязательные смысловые поля:

- `ip` — IPv4 адрес;
- `online` — был ли получен корректный ответ;
- `model` — модель ASIC;
- `boardModel` — объединённые модели плат;
- `boards` — массив до трёх плат;
- `workingBoards` — количество рабочих плат;
- `totalBoards` — обычно `3`;
- `failedBoards` — номера нерабочих плат;
- `ratio` — например `2/3`;
- `status` — состояние ASIC.

## 3. Плата

```json
{
  "number": 1,
  "id": "0",
  "model": "BH42651",
  "chips": 76,
  "hashrateGh": 40000,
  "working": true
}
```

`hashrateGh` хранится в GH/s. Клиент показывает значение в TH/s:

```text
TH/s = GH/s / 1000
```

Отображение выполняется с двумя знаками после запятой.

## 4. Статусы ASIC

### `healthy`

Все три платы рабочие, итог `3/3`.

### `degraded`

Работает одна или две платы. Такой ASIC может участвовать в расчёте микса.

### `check`

Ни одна плата не работает. ASIC требует проверки и не участвует в миксе.

### `offline`

Нет ответа через оба API. Устройство скрыто по умолчанию и доступно при включении переключателя «Показывать офлайн».

## 5. Группа микса

Группа создаётся по `boardModel` и содержит только онлайн ASIC с `1/3` или `2/3`.

Поля:

- `boardModel` — модель hashboard;
- `devices` — все устройства группы;
- `donors` — кандидаты на полное донорство;
- `recipients` — кандидаты на получение плат;
- `usedDonors` — выбранные доноры;
- `usedRecipients` — выбранные реципиенты;
- `unused` — устройства, которые не вошли в текущий баланс;
- `availableBoards` — количество рабочих плат у выбранных доноров;
- `boardTransfers` — число передаваемых плат;
- `suggestedMixes` — число закрываемых до `3/3` реципиентов.

## 6. Расчёт потребности

Для ASIC с тремя слотами:

```text
потребность реципиента = 3 - workingBoards
```

| Исходное состояние | Нужно плат | Состояние после операции |
|---|---:|---|
| `2/3` | 1 | `3/3` |
| `1/3` | 2 | `3/3` |
| `0/3` | не участвует | требуется проверка |
| `3/3` | 0 | не участвует |

Донор отдаёт все свои рабочие платы:

| Донор | Отдаёт | Состояние после операции |
|---|---:|---|
| `2/3` | 2 | `0/3` |
| `1/3` | 1 | `0/3` |

## 7. Печать

Для каждой выбранной машины формируется объект:

```json
{
  "ip": "10.1.38.51",
  "role": "ДОНОР",
  "models": "BH42651, BH42612",
  "failed": "HB 2,3"
}
```

Модели плат собираются через `Set`, поэтому одинаковая модель не дублируется.

В общий результат группы попадают только `usedDonors` и `usedRecipients`.
