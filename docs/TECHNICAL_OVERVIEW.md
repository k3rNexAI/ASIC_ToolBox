# ASIC Mix Control — технический обзор

## 1. Назначение

Локальное веб-приложение для:

- хранения списка ЦОДов и диапазонов IPv4;
- сканирования ASIC с Braiins OS 26.08+;
- определения модели ASIC и моделей hashboard;
- определения рабочих и неисправных плат;
- расчёта микса по модели платы внутри одного выбранного ЦОДа;
- печати этикеток доноров и реципиентов на локальном принтере этикеток.

## 2. Архитектура

Приложение состоит из локального Node.js HTTP-сервера и статического браузерного интерфейса.

```text
Браузер
  │ HTTP localhost:4180
  ▼
server.js
  ├── state.json — список ЦОДов
  ├── TCP 4028 — legacy BOSminer API
  ├── TCP 50051 — Braiins Public API через grpcurl
  └── расчёт групп микса
```

Сканирование выполняется сервером, а не браузером. Пароль ASIC не передаётся в клиентский JavaScript.

## 4. Ограничения

- За один запуск сканируется только один ЦОД.
- Миксы рассчитываются только для одного результата сканирования выбранного ЦОДа.
- Максимальный размер диапазона одного ЦОДа — 4096 IPv4-адресов.
- Одновременно выполняется только один скан.
- Приложение не имеет встроенной пользовательской авторизации.
- По умолчанию HTTP-сервер слушает только `127.0.0.1`.
- Данные ЦОДов хранятся в обычном JSON-файле без базы данных.
- Сетевой доступ к ASIC должен быть разрешён с компьютера, на котором запущено приложение.

## 5. Запуск

### Windows

Запустить двойным кликом:

```text
run-windows.cmd
```

Адрес интерфейса:

```text
http://127.0.0.1:4180
```

### Linux/macOS

```bash
npm start
```

или:

```bash
node server.js
```

Проверка синтаксиса:

```bash
npm run check
```

## 6. Поток сканирования

1. Сервер разворачивает CIDR или диапазон start/end в список IP.
2. IP обрабатываются партиями по 32 адреса.
3. Для каждого адреса сначала выполняются legacy-запросы на TCP 4028.
4. Используется выбранный протокол: только gRPC, только legacy TCP или последовательный fallback gRPC → TCP.
5. Из ответа формируются три платы ASIC.
6. Плата считается рабочей только при положительном признаке enabled, количестве чипов больше нуля и хешрейте больше нуля.
7. После сканирования рассчитываются группы по `boardModel`.

## 7. Результат

Результат сканирования содержит:

- время сканирования;
- список устройств;
- группы миксов;
- фактические причины offline в поле `error`;
- данные плат и текущий хешрейт в GH/s, который в браузере показывается как TH/s с двумя знаками.
