# ASIC Mix Control — конфигурация и изменяемые параметры

## 1. Переменные окружения сервера

| Переменная | По умолчанию | Что меняет |
|---|---:|---|
| `HOST` | `127.0.0.1` | Адрес, на котором слушает HTTP-сервер |
| `PORT` | `4180` | Порт веб-интерфейса |
| `ASIC_USER` | `root` | Логин Braiins OS |
| `ASIC_PASSWORD` | `root` | Пароль Braiins OS |
| `GRPCURL_PATH` | `tools/grpcurl` или `tools/grpcurl.exe` | Полный путь к исполняемому grpcurl |

Пример Linux/macOS:

```bash
HOST=127.0.0.1 PORT=4181 ASIC_USER=root ASIC_PASSWORD=root npm start
```

Пример Windows в `cmd`:

```bat
set "HOST=127.0.0.1"
set "PORT=4181"
set "ASIC_USER=root"
set "ASIC_PASSWORD=root"
run-windows.cmd
```

## 2. Настройки `run-windows.cmd`

В начале файла можно изменять:

```bat
set "HOST=127.0.0.1"
set "PORT=4180"
set "ASIC_USER=root"
set "ASIC_PASSWORD=root"
```

Также можно изменить путь к Node.js, если нужно использовать другой runtime:

```bat
set "NODE=C:\Tools\node.exe"
```

Но штатный файл автоматически выбирает:

1. `runtime\\node.exe` внутри проекта;
2. системную команду `node`, если portable runtime отсутствует.

## 3. Сетевые параметры в `server.js`

Эти параметры сейчас заданы константами и меняются непосредственно в исходнике:

| Параметр | Текущее значение | Назначение |
|---|---:|---|
| порт legacy API | `4028` | TCP-подключение к BOSminer API |
| порт Public API | `50051` | gRPC Braiins Public API |
| timeout legacy-запроса | `1300 ms` | Таймаут одного TCP 4028 запроса |
| timeout grpcurl-процесса | `6000 ms` | Максимальное время grpcurl вызова |
| gRPC `-max-time` | `4 s` | Таймаут grpc-соединения внутри grpcurl |
| размер партии сканирования | `32` IP | Количество параллельных ASIC за один проход |
| режим API по умолчанию | `grpc` | Быстрый режим без обязательного TCP fallback |
| максимум адресов | `4096` | Ограничение одного CIDR/диапазона |
| количество hashboard | `3` | Модель ASIC S19 с тремя платами |
| файл состояния | `state.json` | Путь относительно каталога проекта |
| каталог интерфейса | `public` | Статические HTML/CSS/JS файлы |

## 4. Как менять сетевые параметры

### Выбор протокола в интерфейсе

В панели сканирования доступны два переключателя:

- `gRPC 50051` — основной быстрый Braiins Public API;
- `TCP 4028` — legacy BOSminer API.

Возможные режимы:

- включён только gRPC — выполняется только gRPC;
- включён только TCP — выполняется только TCP 4028;
- включены оба — сначала gRPC, затем TCP только для устройств, на которых gRPC не ответил;
- оба выключены — кнопка сканирования блокируется.

Протоколы не запускаются одновременно для одного ASIC. Для ускорения скана рекомендуется оставить включённым только `gRPC 50051`.

В `server.js`:

```js
const PORT = Number(process.env.PORT || 4180);
const HOST = process.env.HOST || '127.0.0.1';
```

Порты ASIC меняются в двух местах:

- `net.createConnection({ host: ip, port: 4028 })`;
- строка grpcurl `${ip}:50051`.

Если используется другой ASIC API или прокси, нужно менять функции `apiCall`, `grpcCall`, `scanOne` и `gRPCScanOne`.

## 5. Параметры проверки платы

В gRPC-режиме рабочая плата определяется функцией `boardIsWorking`:

```js
board.enabled !== false &&
chipCount(board) > 0 &&
boardHashrateGh(board) > 0
```

Изменяемые критерии:

- считать ли `enabled=false` неисправностью;
- минимальное количество чипов;
- минимальный хешрейт;
- набор полей ответа API для чтения чипов;
- набор полей ответа API для чтения хешрейта.

В legacy-режиме плата считается рабочей при:

- наличии board/dev-строки;
- отсутствии статуса `dead`, `offline`, `disabled`, `error`, `fail`;
- `GHS 5s` или `GHS av` больше нуля.

## 6. Параметры интерфейса

В `public/app.js` можно менять:

| Параметр | Где | Назначение |
|---|---|---|
| формат TH/s | `formatGh` | Деление GH/s на 1000 и количество знаков |
| скрытие 3/3 | `renderResults` | Фильтр здоровых устройств |
| скрытие offline | `renderResults` | Фильтр недоступных устройств |
| текст статусов | `statusChip` | Подписи OK/ПРОВЕРИТЬ/OFFLINE |
| размер окна печати | `window.open` | Окно предпросмотра этикеток |
| ширина этикетки | `@page` и `.label` | Сейчас 58 mm |
| минимальная высота этикетки | `.label` | Сейчас 32 mm |
| размер IP | `.ip` | Сейчас 16 pt |
| размер роли | `.role` | Сейчас 8 pt |
| размер модели платы | `.models` | Сейчас 9 pt |
| размер неисправных плат | `.failed` | Сейчас 14 pt |

## 7. Параметры печати

Шаблон печати создаётся в браузере функцией `printLabelEntries`.

Изменяемые элементы:

- `@page { size: 58mm auto; margin: 0 }` — формат рулона;
- `.label { width: 58mm }` — ширина этикетки;
- `.label-head` — строка IP и роли;
- `.ip` — последние две части IP;
- `.role` — `ДОНОР` или `РЕЦИПИЕНТ`;
- `.models` — уникальные модели плат без повторов;
- `.failed` — неисправные платы, например `HB 1,3`;
- `window.print()` — открытие стандартного диалога печати Windows.

Для другого рулона обычно меняют `58mm` одновременно в `@page` и `.label`.

## 8. Параметры расчёта микса

Основная функция: `mixes` в `server.js`.

Изменяемые правила:

- группировка: `boardModel || model`;
- допустимые устройства: только `workingBoards === 1` или `2`;
- количество плат ASIC: `3`;
- приоритет реципиентов: устройства с меньшей потребностью закрываются первыми, то есть `2/3`, затем `1/3`;
- донор отдаёт все свои рабочие платы;
- донор после операции считается `0/3`;
- реципиент после операции считается `3/3`;
- лишние устройства попадают в `unused` и не печатаются кнопкой результата группы.

## 9. Изменение модели ASIC

Текущая логика рассчитана на 3 платы. Для ASIC с другим количеством плат нужно изменить минимум:

- `expected = 3` в legacy-сканере;
- `const expected = 3` в gRPC-сканере;
- генерацию строк плат в клиенте `Array.from({ length: 3 })`;
- формулу `3 - workingBoards` в расчёте миксов;
- подписи интерфейса `3/3`;
- фильтры и печатный шаблон.

## 10. Хранение данных

`state.json` можно редактировать вручную при остановленном сервере. После ручного изменения используйте валидный JSON и сохраните резервную копию.

Удаление ЦОДа через интерфейс безвозвратно удаляет его запись из файла. Результаты последнего сканирования в `state.json` не сохраняются.

## 11. Настройки безопасности

- Для локального ПК оставляйте `HOST=127.0.0.1`.
- Не ставьте `HOST=0.0.0.0`, если не требуется доступ с других компьютеров.
- Не публикуйте порт в интернет.
- Не храните пароль ASIC в публичном Git-репозитории.
- Если меняется пароль, задайте `ASIC_PASSWORD` в окружении или `run-windows.cmd`.
- Для production-сети нужны TLS, аутентификация пользователя и журналирование — сейчас их нет.
